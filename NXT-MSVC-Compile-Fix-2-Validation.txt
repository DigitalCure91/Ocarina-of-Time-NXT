Ocarina of Time NXT — MSVC compile/link fix 2 validation
Date: 11 October 2026

SOURCE BASE
Initial OcarinaOfTime-NXT-RPG-Source.zip plus compile fix 1 and the corrections
listed in this package. Tests use the uploaded project's real engine headers.

FINAL MATRIX
GCC 14.2, Debug:   -Werror, AddressSanitizer + UndefinedBehaviorSanitizer; passed.
GCC 14.2, Release: -Werror; passed.
Clang 17, Debug:   -Werror, AddressSanitizer + UndefinedBehaviorSanitizer; passed.
Clang 17, Release: -Werror; passed.
For both sanitized runs:
  ASAN_OPTIONS=detect_leaks=1:halt_on_error=1
  UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1
Each configuration built AND linked the two standalone executables, and both
CTest entries passed. The simulation reports 15 groups / 520216 assertions.
Most assertions are arithmetic loops, not distinct gameplay scenarios.

ACTOR LINK REGRESSION
The actual production NxtActors.cpp is compiled separately from NxtActorLinkTests.cpp.
All its external functions are resolved against real-header-checked test fixtures
and the standard runtime; unresolved-symbol errors are not suppressed.
The executable invokes the registered actor draw callback for 9 fixture cases:
child bot, adult bot, ordinary enemy, each of the five world-boss telegraphs, and
telegraph vertex-allocation failure. Fifteen interpolation scopes balance.
Debug graph scopes and matrix scopes are checked as well.
The rendering engine/resource boundaries are mocked. These tests do not verify
actual assets, visual output, the interpolation algorithm, or scene correctness.

NEGATIVE CONTROLS
The new actor target was rebuilt with the original NxtActors.cpp: linkage failed
with both missing C++-mangled interpolation symbols, as expected.
The same target with only a global frame_interpolation.h include also failed
with both symbols. Restoring the namespace-scoped C declarations linked.
GCC and Clang object-symbol audits found only the expected plain C names after
the fix, not Nxt-scoped/mangled alternatives.

ADDITIONAL ABI CHECK
A small isolated x64 Windows-ABI reproducer using the same declaration pattern
compiled with clang-cl /W4 /WX and linked with lld-link against a separate C-ABI
provider. It produced a PE executable; it was not executed. This is NOT an MSVC
compilation of NxtActors.cpp or a Windows game build.

SANITIZER FINDING
The first Clang sanitized simulation run exposed the old direct conversion of
float +32768 to int16_t in NxtCombat.cpp. This was not silently ignored: the four
angle-conversion call sites were updated to a shared, bounded DirectionYaw helper.
The expanded 15-group suite then passed under both sanitized compilers.

LIMITATIONS
No full Visual Studio/MSVC game compile/link or executable launch was performed.
No GPU rendering, ROM assets, real Hyrule maps, GUI or save integration was tested
by these fixtures. This is a tested source patch for the reported linkage failures
and the additional angle-conversion defect, not a claim of a finished game release.
The production interpolation implementation and game build flags are unchanged.

REPRODUCTION ON LINUX (from the updated source root)
cmake -S tests/nxt -B build/nxt-tests-check -G Ninja -DCMAKE_BUILD_TYPE=Debug -DNXT_SANITIZE=ON -DCMAKE_CXX_FLAGS=-Werror
cmake --build build/nxt-tests-check --parallel 4
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1 ctest --test-dir build/nxt-tests-check -V --output-on-failure
